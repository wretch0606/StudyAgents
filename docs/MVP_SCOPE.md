# 一周 MVP 范围与验收标准

> 状态：执行基线｜版本：V1.0｜负责人：成员 A（组长）｜周期：7 天
>
> 目标：完成可在答辩现场稳定演示的单课程可信知识问答与专项复习原型。

## 1. 范围判定原则

本文件将《多 Agent 知识问答复习系统开发文档》V1.0 的 2–3 周首版设计，收敛为《StudyAgents 五人一周合作分工方案》V1.1 的一周执行范围。出现冲突时，按以下顺序判断：

1. 本文件定义的一周 MVP 范围与验收标准。
2. 《StudyAgents 五人一周合作分工方案》V1.1。
3. 《多 Agent 知识问答复习系统开发文档》V1.0。

任何新增需求必须先说明它替代或推迟哪一项现有工作，不得在未完成核心闭环时扩展功能。

## 2. 核心演示闭环

答辩版本必须完整跑通：

```text
预置账号登录
  → 管理员导入课程 PDF
  → 系统完成解析、OCR、切块和索引
  → 成员提出资料内问题并获得带来源回答
  → 成员提出资料外问题并获得明确拒答
  → 成员完成至少 3 题专项训练
  → 系统返回评分、讲解、错题和掌握度变化
```

页面应展示协调、知识、出题、评测讲解四类 Agent 的公开步骤摘要，但不得展示思维链、标准答案、评分点或私有证据。

## 3. 必须完成

| 编号 | 能力 | 最低交付 | 验收标准 |
| --- | --- | --- | --- |
| MVP-AUTH-01 | 登录与权限 | 五个预置本地账号，其中一个为管理员 | 正确凭据可登录；错误凭据返回统一错误；普通成员访问管理接口返回 `403`；成员只能访问自己的记录 |
| MVP-KB-01 | 数字 PDF 导入 | 管理员可上传数字 PDF 并完成解析、切块与索引 | 上传后能看到任务状态；完成后可检索；来源保留文档名和页码；失败状态可见 |
| MVP-KB-02 | 扫描 PDF 基础 OCR | 对印刷体扫描 PDF 完成基础 OCR 和索引 | 样例扫描件可提取可检索文本；低置信度页可标记复核，不允许伪造成功结果 |
| MVP-QA-01 | 可信问答 | 返回结论、依据与步骤、来源和置信提示 | 每个关键结论至少包含一个有效的文档名与页码或题号引用 |
| MVP-QA-02 | 严格拒答 | 证据不足时进入拒答流程 | 不使用模型常识补全答案；说明无法确认的内容、检索范围和建议补充的资料 |
| MVP-AGENT-01 | Agent 过程可见 | 展示四类 Agent 的公开事件摘要 | 能看到角色、状态、摘要、耗时和引用；不显示思维链和私有字段 |
| MVP-TRAIN-01 | 专项训练 | 完成至少 3 题的一轮训练 | 用户可作答；每题返回得分、分步反馈、讲解、引用和置信度；训练结束显示总分 |
| MVP-LEARN-01 | 错题与掌握度 | 低分题进入错题本并更新掌握度 | 得分率低于 `80%` 或标记“不确定”时生成或更新错题；掌握度变化有明确原因 |
| MVP-SEC-01 | 防答案泄露 | 公共对象与私有评分数据隔离 | 提交答案前的 REST、SSE、日志和前端状态不含标准答案、评分点或私有证据 |
| MVP-RUN-01 | 可复现启动 | Docker Compose 或统一启动脚本 | 在答辩电脑按说明完成启动；准备模型不可用时的演示缓存；关键错误含 `trace_id` |

## 4. 有余力再做

以下工作只能在第 2、4、6 天集成门均通过且核心缺陷清零后开始：

- DOCX、PPTX、JPG、PNG 的完整导入兼容。
- 多轮问答历史体验优化和非核心筛选。
- 管理端批量编辑、复杂统计图和视觉动画。
- 更丰富的题型、训练配置与个性化建议。
- 大规模检索参数调优和完整监控面板。

## 5. 本周明确不做

- 多课程和跨课程检索。
- 公开注册、统一身份认证、教师端、班级管理和公开题库。
- 音视频课程、网页爬取、重度手写识别和手写作答照片判分。
- 原生 Android/iOS 应用。
- 本地大模型部署。
- PDF、Excel 等个人报告导出。
- 与核心演示无关的视觉重构和性能优化。

## 6. 核心验收用例

| 用例 | 操作 | 预期结果 | 主要负责人 |
| --- | --- | --- | --- |
| AC-01 登录与越权 | 分别使用管理员和普通账号登录；普通账号请求管理接口 | 两类账号均可登录；普通账号收到 `403`；其他成员数据不可见 | D、E |
| AC-02 数字 PDF 导入 | 管理员上传指定数字 PDF 并等待任务完成 | 页面显示任务状态；完成后可检索；SourceRef 可定位文档和页码 | B、D、E |
| AC-03 扫描 PDF 导入 | 上传指定印刷体扫描 PDF | OCR 文本可检索；低置信度有明确状态；失败不产生半激活索引 | B、D |
| AC-04 有证据问答 | 提问评测集中一个资料内问题 | 回答正确且关键结论带有效引用；公开 Agent 摘要完整 | B、C、D、E |
| AC-05 无证据拒答 | 提问评测集中一个资料外问题 | 明确拒答，不夹带资料外答案，并给出补充资料建议 | C、E |
| AC-06 训练评分 | 完成至少 3 题训练并提交客观题与主观题答案 | 返回总分、分项反馈、讲解、引用和置信度；提交前无答案泄露 | C、D、E |
| AC-07 错题沉淀 | 提交一个低于 `80%` 的答案或标记“不确定” | 错题本新增或更新记录；掌握度发生可解释变化 | C、D、E |
| AC-08 故障可见 | 模拟模型超时、无效 JSON 或 SSE 断线 | 显示明确错误或重试状态；最多重试两次；可定位 `trace_id` | C、D、E |
| AC-09 部署复现 | 在干净环境按仓库说明启动并执行完整闭环 | 实时模式或演示缓存模式可用；完整闭环连续成功 3 次 | A、D、E |

## 7. 答辩版本质量门槛

| 类别 | 指标 | 门槛 |
| --- | --- | --- |
| 检索 | `Recall@5` | `>= 85%` |
| 回答 | 人工判定正确率 | `>= 80%` |
| 引用 | 引用准确率 | `>= 90%` |
| 拒答 | 应拒答识别率 | `>= 80%` |
| 评分 | 计算题、简答题与人工评分可接受一致率 | `>= 80%` |
| 性能 | 云 API 正常时最终响应 `P95` | `<= 30 秒` |
| 过程 | SSE 首个状态事件 | `<= 2 秒` |
| 成本 | 开发、评测与答辩累计模型费用 | `<= 100 元` |
| 闭环 | 现场完整演示链路 | `100% 跑通，连续成功 3 次` |
| 安全 | 未解决的高风险安全缺陷 | `0` |

质量指标使用成员 A 维护的 50 条人工评测集。若第 6 天仍未达到门槛，必须冻结新功能并形成带负责人、复现步骤和影响范围的缺陷清单。

## 8. 一周 Definition of Done

一项功能只有同时满足以下条件才可标记为完成：

- 代码已通过 Pull Request 合并，且至少一名非主责成员完成评审。
- 正常流程和主要错误流程均可运行。
- 单元测试、契约测试或对应自动化测试已通过。
- 权限和私有字段隔离已验证。
- 错误响应与日志包含可定位问题的 `trace_id`。
- 接口契约、Mock 数据和必要说明已同步更新。
- 已在集成环境按对应验收用例运行成功。

只在个人电脑上“能跑一次”，或仅完成界面但未接通真实数据，均不算完成。

## 9. 范围变更规则

- A 维护本文件和范围变更记录。
- 影响公共字段时，先修改 `contracts/` 中的 Schema 与示例，再修改各模块。
- 第 2、4、6 天结束前进行集成验收；未通过时，次日先修复主链路。
- 第 7 天冻结功能，只允许修复阻塞演示或高风险安全问题。
- 任何范围变更均通过 Issue 或 ADR 记录原因、取舍、负责人和验收影响。
